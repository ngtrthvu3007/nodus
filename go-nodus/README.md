# go-nodus

The Nodus backend: a Go HTTP API (Gin + GORM + Postgres) and an MCP server for AI agents. Database migrations are generated and applied by [Atlas](https://atlasgo.io), which runs in Docker — nothing to install besides Go, Docker and `make`.

## How it is organized

```text
go-nodus/
├── cmd/
│   ├── api/main.go        # reads config, opens the database, starts the HTTP server
│   └── mcp/               # MCP server (stdio); talks to the HTTP API, never to the database
├── internal/
│   ├── api/               # the whole HTTP API, one file per domain
│   │   ├── server.go      # router, CORS, response envelope, error mapping, request binding
│   │   ├── notes.go       # /notes — CRUD, move, the 2-level note tree rules
│   │   ├── folders.go     # /folders
│   │   └── links.go       # [[wiki-links]], backlinks, title autocomplete
│   ├── config/config.go   # environment variables
│   └── db/models.go       # GORM models — the single source of the schema
├── migrations/            # SQL generated by Atlas, plus atlas.sum (checksums)
├── atlas.hcl              # Atlas config
└── docker-compose.yml     # postgres, plus the Atlas containers (migrations only)
```

A request goes through one handler that reads top to bottom: bind and validate the input → check the domain rules → query Postgres with GORM → write the response. Responses always use the same envelope:

- success: `{ "success": true, "data": … }`
- error: `{ "success": false, "error": { "code": "note_not_found", "message": "Note is not found" } }`

Every route is listed in [docs/backend-map.md](../docs/backend-map.md); the business rules live in [docs/frd/](../docs/frd/).

## First run

```bash
cp .env.example .env     # the defaults work as-is
docker compose up -d     # Postgres on localhost:5432 (Atlas containers do not start)
make migrate-up          # create the schema
make dev                 # API with hot reload on http://localhost:8080
curl localhost:8080/health
```

If port 5432 is already used by a local Postgres, change the published port in `docker-compose.yml` and in `DATABASE_URL`.

## Configuration

`.env` (copied from `.env.example`):

- `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — the Postgres container.
- `DATABASE_URL` — used by the API.
- `PORT` — API port, default `8080`.
- `ALLOWED_ORIGIN` — the frontend allowed to call the API from the browser (`next-nodus`: `http://localhost:4000`).
- `GIN_MODE=release` in production (less logging).

## Changing the database schema

The GORM models in `internal/db/models.go` describe the schema; Atlas writes the SQL. Never call `AutoMigrate`.

1. Edit the models (add a field, a struct, an index tag…).
2. Generate the migration:
   ```bash
   make migrate-diff NAME=add_note_position
   ```
   Atlas compares the models with the existing migrations and writes `migrations/<timestamp>_add_note_position.sql`.
3. Read the generated SQL. If you add something GORM tags cannot express (a partial index, a CHECK constraint), edit the file, then run `make migrate-hash`.
4. Apply it:
   ```bash
   make migrate-up
   ```
5. Commit the models and the migration together.

Never edit or delete a migration that has already been applied or pushed — add a new one.

## Undoing a migration

Atlas migration files only go forward (no `.down.sql`). To undo:

- **Already pushed or deployed** — roll forward: revert the change in the models and run `make migrate-diff` again; Atlas generates the reverse SQL as a new migration.
- **Only on your local database** — let Atlas revert it:
  ```bash
  make migrate-down-plan N=1   # print the SQL that would run, change nothing
  make migrate-down N=1        # revert the last migration
  ```
  Atlas checks before reverting and refuses to drop tables or columns that still hold data.

## How the Atlas containers run

- `docker compose up` starts Postgres only. The Atlas services (`atlas-migrate-runner`, `atlas-dev-db`) belong to the `tools` profile and start only through `make migrate-*`.
- The runner is removed after every command. The scratch database `atlas-dev-db` (in memory) exists only while a diff or a rollback runs.
- If a command was interrupted and left a container behind: `make migrate-clean`.
- The Atlas version is pinned by the image tag in `docker-compose.yml`.

## MCP server

Lets AI agents (Claude Code, Claude Desktop, Cursor…) read and write notes through the HTTP API. The API must be running.

```bash
go build -o bin/nodus-mcp ./cmd/mcp
claude mcp add nodus -e NODUS_API_BASE=http://localhost:8080 -- "$(pwd)/bin/nodus-mcp"
```

Rebuild the binary after changing `cmd/mcp` or the models.

## Commands

Run inside `go-nodus/`.

- `make dev` — API with hot reload (Air). Without hot reload: `go run ./cmd/api`.
- `make migrate-diff NAME=<name>` — generate the next migration from the models.
- `make migrate-up` — apply pending migrations.
- `make migrate-status` — show applied and pending migrations.
- `make migrate-hash` — update `migrations/atlas.sum` after editing a migration by hand.
- `make migrate-down-plan N=1` — show the SQL that would revert the last N migrations.
- `make migrate-down N=1` — revert the last N migrations (local databases only).
- `make migrate-clean` — remove Atlas containers left by an interrupted command.
- `go vet ./...` — static checks.
